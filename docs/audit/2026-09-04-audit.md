## 0. Головний висновок

**Тести — не причина.** Весь suite (52 файли, 1249 тестів, 11.8k LOC) виконується за
**12 с** (з них самі тести — 1.3 с, решта — імпорт модулів). У Docker-збірці на VPS vitest
взагалі не запускається. Внесок тестів у `tsc`/`next build` — ~1 с (типізація `tests/`
через `tsconfig.include: ["**/*.ts"]`).

**Справжні причини дорогого деплою** (`.github/workflows/deploy.yml`, `Dockerfile`):

| # | Проблема | Де | Ціна |
|---|---|---|---|
| 1 | `next build` виконується **на VPS**, з холодним Turbopack-кешем, кожен пуш | `deploy.yml:154`, `Dockerfile:25` | домінуюча; на 1–2 vCPU це хвилини |
| 2 | Образ будується **двічі** за деплой: `docker compose build app tools` → потім `docker compose up -d --build` | `deploy.yml:154,168` | повторна передача контексту + переоцінка шарів |
| 3 | `COPY . .` + куций `.dockerignore` (7 рядків): `tests/`, `scripts/`, `.claude/` (71 tracked файл, 3.7 MB), `.github/`, `*.md`, `tsconfig.tsbuildinfo`, `.DS_Store` — усе інвалідовує шар build | `Dockerfile:16`, `.dockerignore` | будь-яка правка runbook = повний rebuild |
| 4 | Повний `tsc` **двічі**: у CI (`npm run typecheck`) і всередині `next build` (Next 16 типізує, але не лінтить) | `deploy.yml:26`, `next build` | 10–90 с залежно від CPU |
| 5 | `npm ci` **×3** (job `ci`, job `verify-db`, Docker `deps`), `prisma generate` **×6** (postinstall + явний виклик у кожному місці) | `deploy.yml:20,22,57,59`, `Dockerfile:9,25` | 1–3 хв runner-часу |
| 6 | `tools`-образ = `FROM build` → повний образ з `node_modules` (1.2 GB) + `.next`, лише для `prisma migrate` | `Dockerfile:27` | диск, час | 
| 7 | `verify-db` job: окремий runner, `npm ci`, міграції, seed ×2, 60-рядковий inline CJS скрипт | `deploy.yml:34-128` | ~2–3 хв паралельно, затримує `deploy` |

Оцінка після виправлення (§6 плану): push → healthy ≈ **CI ~2 хв + build у GHA ~1–2 хв
(теплий кеш) + deploy на VPS < 1 хв**, VPS більше не компілює нічого.

> Невідома змінна: `nproc` / `free -m` на VPS. Якщо там 1 vCPU / 2 GB — пункт 1 не
> опційний, це головний пожирач часу.

## 1. Загальна картина

- Next.js 16.3 (App Router, Turbopack, server actions), React 19, Prisma 7 + `@prisma/adapter-pg`,
  Postgres 16, Gotenberg (PDF), Tailwind 4, base-ui/shadcn, Tiptap.
- `src/`: 216 файлів / 32.4k LOC. `tests/`: 52 файли / 11.8k LOC (36 % від src).
- 31 сторінка, 6 API-роутів, 57 client-компонентів (9.7k LOC).
- Деплой: GHA → SSH на VPS → `git pull` → `docker compose build` → `migrate` → `up`.

Шари (read = queries, write = actions):

```
pages (RSC) ──► lib/queries/*.ts ──► db (Prisma)
client comps ─► lib/actions/*.ts ("use server")
                    ├ zod   lib/validation/*
                    ├ authz lib/authz.ts → auth.ts (JWT, 5-хв реваліда з БД)
                    ├ domain lib/pricing.ts (bigint-cents, чистий)
                    └ db + $transaction

document read-model:
 queries/documents.getDocumentForBuilder
   ├ computeTotals (pricing) + buildItemBreakdown (sheet-data)
   └ toSheetData → buildQuotationData → pdf.ts → components/sheet/quotation-sheet.tsx → Gotenberg
```

Що добре (коротко, щоб не зламати): гроші рахуються в bigint-центах; чисті модулі не
імпортують `@/lib/db`, тому тести гермети (0 `vi.mock`, 0 `.only`, 0 sleep, 0 мережі);
params/searchParams як Promise (Next 16 compliant); ordering migrate → up правильний;
health check перевіряє схему.

## 2. Pipeline / збірка — деталі

### 2.1 Шлях `git push main` → healthy container

| Крок | Що | Вердикт |
|---|---|---|
| CI `ci` | `npm ci` (postinstall = `prisma generate` #1) → `npx prisma generate` #2 → lint → `next typegen && tsc` → `vitest` | generate #2 зайвий |
| CI `verify-db` | `npm ci` знову → generate #3, #4 → migrate → seed ×2 → inline count-check | дубль install; скрипт дублює знання seed'у |
| VPS | `git pull` → `docker compose build app tools` (deps: `npm ci` #3 + generate #5; build: `COPY . .`, generate #6, `next build` з tsc) | головна ціна |
| VPS | `docker compose up -d postgres` → `run tools migrate deploy` → **`up -d --build`** (rebuild #2) → health loop | другий build зайвий |

Разом: `npm ci` ×3, `prisma generate` ×6 (потрібно 2), `tsc` ×2, `docker build` ×2.

### 2.2 Заміри (пісочниця, 4 vCPU, macOS node_modules)

| Крок | Час |
|---|---|
| `vitest run` (default, forks, isolate) | 12.3 с (import 15.9 с cum., tests 1.3 с) |
| `vitest run --isolate=false --pool=threads` | **5.1 с** — усі 1249 зелені |
| `tsc --noEmit` з `tests/` / без | 10.5 с / 9.6 с (за даними агента) |
| `npm run typecheck` (incremental) | 5.4 с |
| `npm run lint` (весь репо, incl. tests/scripts/prisma) | 13.2 с |
| `next build` | не заміряно: Turbopack не приймає symlink node_modules, а Linux `npm ci` не вкладається у ліміт пісочниці. **Заміряти на VPS**: `time docker compose build app` + `nproc`, `free -m`. |

### 2.3 Dockerfile / контекст

- `.dockerignore` пропускає: `tests/`, `scripts/`, `.claude/`, `.github/`, `data/`, `*.md`,
  `tsconfig.tsbuildinfo`, `.DS_Store`, `docker-compose*.yml`, `Dockerfile`, `vitest.config.ts`,
  `eslint.config.mjs`. Контекст ≈ 569 файлів при 468 tracked.
- `ENV DATABASE_URL=... AUTH_SECRET=placeholder` (`Dockerfile:23-24`) живе в шарі `build` і,
  через `FROM build`, у `tools`-образі. Запуск `tools` без `env_file` тихо піде на
  `localhost:5432` з placeholder-секретом. Має бути `ARG` або окремий тонкий `tools`.
- Run-образ тягне `prisma/` цілком (7 MB `seed-data/product-images`), хоча seed запускається лише з `tools`.
- Немає `HEALTHCHECK`, контейнер працює від root, `app` не має `depends_on: condition: service_healthy` на себе — `restart: unless-stopped` крутитиме краш-луп.
- `prisma.config.ts` і `prisma/seed.ts` імпортують `dotenv/config`, але `dotenv` відсутній у `package.json` (транзитивно з `prisma`). Bump Prisma може зламати postinstall.
- `shadcn` (CLI) у `dependencies`; `prisma` CLI також. `xlsx` коректно в dev.
- `.next/` локально = 2.3 GB (dev-кеш) — не впливає на деплой, але варто знати.

### 2.4 Next.js

- `output: "standalone"` — ок. `next build` у Next 16 **типізує, але не лінтить** — тому CI typecheck + in-build typecheck = чистий дубль. Варіанти: `typescript.ignoreBuildErrors` лише в Docker (через env), або звузити `tsconfig.include` до `src/**` + `prisma/**`, винести `tests/`+`scripts/` в окремий `tsconfig`.
- `experimental.turbopackFileSystemCacheForBuild` за замовчуванням увімкнено — у Docker-шарі кеш пишеться і викидається. Або монтувати `--mount=type=cache,target=/app/.next/cache`, або вимкнути.
- Немає `optimizePackageImports`, немає жодного `next/dynamic` у репо.

### 2.5 CI verify-db

Захищає від реального класу помилок (інцидент 2026-08-31), але:
- окремий runner + другий `npm ci`;
- inline CJS-скрипт (`deploy.yml:71-128`) не може імпортувати `seed-lib.ts`, тому дублює знання про seed і вже дрейфував один раз;
- seed виконується двічі заради idempotency, яку дешевше перевірити тестом.

Заміна: у той самий job `ci` додати `services: postgres`, `prisma migrate diff --exit-code`
(schema без міграції), один `migrate + seed`, а перевірку лічильників — у vitest-тест,
що вмикається тільки за `DATABASE_URL`. Або тригерити verify-db лише на `paths: prisma/**`.

## 3. Архітектура і кодова база (`src/lib`)

### 3.1 God-файли і дублювання

- **`actions/documents.ts` — 1927 LOC**. Містить recalc-glue (100–350), lifecycle (360–440), client assignment (457–505), items (528–690), options + conflict/compat/EasyLoader (725–980), custom lines (986–1095), discount-повідомлення (1102–1175), price overrides (1177–1500), presentation toggles (1507–1830), validity/delivery (1830+). Приблизно **14 разів** повторюється той самий 25-рядковий шаблон «знайти scoped DRAFT item → `$transaction` → `recalcAndEnforce` → зловити два sentinel-и → `revalidatePath`» (`:565-604`, `:634-644`, `:1019-1046`, `:1081-1091`, `:1270-1286`, `:1358-1374`, `:1402-1412`, `:1443-1459`, `:1485-1495`). Обгортка `withDraftMutation(itemId, role, fn)` прибирає ~300 LOC.
- `actions/catalog.ts` (632) — products/options/images/prices/compat/conflict-groups в одному файлі. `queries/documents.ts` (949) — list + builder DTO + forms + pickers.
- **`ActionResult`, `NOT_FOUND_ERROR`, `flattenZodError` продубльовані у 12 файлах** actions (бо `"use server"`-модуль експортує тільки async-функції). Рішення: `actions/_shared.ts` без директиви.
- Мапінг Decimal → `EngineInput` скопійований дослівно: `actions/documents.ts:230-262` і `queries/documents.ts:540-575` (разом з двокроковим fetch `optionNoCommissionMap`). Потрібен один `buildEngineInput()`. Плюс `Number(item.unitPrice)` робить зайвий хоп через float — engine приймає string.
- `identityResolver` визначений у `sheet-data.ts:225` і `quotation-data.ts:37`.
- `regionCodeSchema` існує **тричі** (`validation/content.ts:60`, `regions.ts:15`, `clients.ts:116`) + `userRegionCodeSchema` (`users.ts:57`); `validityDaysSchema` (documents) vs `quoteValidityDaysSchema` (settings) — одне й те саме 1..365. Тести це теж тестують тричі.
- `pricing.ts` (1161): ~45 % — doc-коментарі; `formatPct/concessionCapMessage/markupCapMessage` (`:1054-1161`) тягнуть `format.ts` у «чистий» engine.

### 3.2 Безпека / авторизація

- Модель: JWT `uid/role/regionId`, `requireSession` (redirect) / `requireAdmin` (throw). Region-scoping ніде не enforced — MANAGER обмежений author/owner (відповідає spec §6). Вибірка 10 actions — усі мають перевірки.
- **Знахідка:** `recalcDocument` (`actions/documents.ts:180`) — `export async function` у `"use server"`-модулі **без перевірки сесії**. Next реєструє її як окремий server-action endpoint: маючи action id, можна переписати `subtotal/taxAmount/total` будь-якого документа, включно з FINAL. Імпортується лише з `finalize.ts:11`. Перенести в `lib/documents/recalc.ts` (не action).
- `requireAdmin` кидає, `requireSession` редіректить — throw з action = Next 500 замість `{error}`.
- `industries.ts`: `createIndustry` = будь-який менеджер, `renameIndustry` = admin. Задокументовано, але асиметрично.

### 3.3 Транзакції / гонки

- `finalize.ts:63`: `recalcDocument` поза `$transaction` (`:149`) — мутація між recalc і `updateMany` фіналізує застарілі суми.
- Мутації перевіряють `status:"DRAFT"` pre-read'ом (`documents.ts:1515`), але не в самій tx — `addItem` під час `finalize` може додати item у FINAL документ. Потрібен `updateMany where status:"DRAFT"` всередині tx.
- `recalcDocument` читає `db.option` / `getCommissionTiers()` через глобальний `db`, а не через `tx` (`:220-224`) — читання поза транзакцією + друге з'єднання з пулу.
- `setItemOptions` (`documents.ts:855-880`) і `applyScreenSideToQuote` (`production.ts:117-133`) — `for…await create` у tx замість `createMany`.
- `unfinalizeDocument` — bare update без audit trail.

### 3.4 Запити / N+1 / кеш

- `getItemPickerCatalog` (`queries/documents.ts:811-836`): `listSeriesWithCounts` + per-series `listProductsBySeries` (кожен = `findUnique` + `findMany include prices{include region}`) → ~2×series+1 запитів на кожне відкриття builder'а, з повними `Region`-рядками. Один `product.findMany` вистачає.
- `getDocumentForBuilder` викликається **двічі** на запит (`generateMetadata` + page) і не обгорнутий у React `cache()`. Те саме у `quotation/page.tsx`, `clients/[companyId]`, `catalog/[seriesId]`, усіх `settings/*/[id]`. `cache()` є лише у 2 функціях (`queries/catalog.ts:15,194`).
- `getQuoteValidityDays` / `getCommissionTiers` — на кожен виклик, без memo (builder query, page, кожен recalc).
- `documents/[documentId]/page.tsx`: 5 послідовних round-trip'ів + 1 з metadata (`auth → getDocumentForBuilder → getHiddenCatalogIds → Promise.all → listCompatibleOptions fan-out`).
- `listDocuments`, `listCompanies` без `take`; builder отримує **усі** компанії + контакти як props (`listClientPickerCompanies`).
- `revalidatePath` — 89 викликів з ручними рядками; друкарська помилка = тихо застарілий UI.

### 3.5 Модель даних

- Відсутні індекси на полях, за якими реально фільтрують: `Product.seriesId`, `Document.contactId`, `Document.updatedAt` (сортування списку), `DocumentItem.productId`, `DocumentLine(kind, refId)`, `OptionCompatibility.seriesId/productId`, `ContentBlock.regionId`, `CatalogVisibility.seriesId/productId`.
- JSON-колонки без гарантій форми: `Region.bankDetails`, `Product.specs`, `Option.attributeSchema`, `DocumentLine.attributes`, `DocumentItem.productionSpec`, `Document.entitySnapshot`, `Setting.value`. Кожен reader ревалідує вручну.
- `Document`: 9 nullable колонок через «порожній draft»; інваріанти (FINAL ⇒ number, entitySnapshot) не виражені. `Series.maxDiscountPct` — задокументовано мертва колонка, але ще читається (`getItemPickerCatalog:824`).
- **Іменування міграцій**: Prisma застосовує папки лексикографічно. `10_industry…` < `1_company_owner`; префікс `z10…z29` — костиль, який зламається на `z100` і блокує `migrate dev`. Перейменувати на timestamp'и одноразовим скриптом по `_prisma_migrations`.

### 3.6 Runtime hot spots

- PDF (`pdf.ts:150-165`): синхронний `readFileSync` кожного зображення, base64 оригіналів (без derivatives) у HTML для Gotenberg — мультимегабайтні payload'и; `renderToStaticMarkup` у request-thread; 30 с timeout, без обмеження конкурентності.

## 5. Тести

Suite дешевий і цінний; питання — у формі, не в кількості.

- 0 моків Prisma (`scope.test.ts` перевіряє `where`-об'єкти). Це наслідок дисципліни «чисті модулі не імпортують db» — **зберегти**.

- Validation-тести: 10 файлів, 2.8k LOC, 423 кейси — тестують реальні межі/регекси проекту, не zod, але 158 з 423 — однорядкові boundary-assertion у 4-рядкових `it()`. `test.each` використано **1 раз** на 1249 тестів.
- Фікстури: `item-breakdown.test.ts:8-64` — побайтова копія `sheet-data.test.ts:38-95`; схожі `baseDoc/baseItem/baseQuotationData` у quotation-data (106 LOC), pdf (95), production-forms-context (46), resolve (37), finalize, catalog-visibility. ~400 LOC фікстур, ~150 дубльованих.
- `catalog.test.ts` (665): ~35 з 50 тестів — literal snapshot `catalog.json` («exactly 66 products», «M3180 = 175000»). Ламається на кожній навмисній правці каталогу; CI verify-db вже виводить лічильники з JSON. Аналогічно `us-prices` (8 spot-price), `seed-mapping` (count smoke).

- Не колокейтити у `src/` — потрапить у compile-graph Next і tsconfig.

## 6. Пріоритети (value / effort)

### Tier 0 — деплой (найбільший ефект)

1. Збірка образу в GitHub Actions (`docker/build-push-action`, `cache-from/to: type=gha`, `RUN --mount=type=cache,target=/app/.next/cache`) → push у GHCR → на VPS `docker compose pull && up -d`. VPS перестає компілювати; `git pull` і SSH-ідентичність до GitHub зникають з критичного шляху.
2. Пропустити typecheck у Docker-build (`typescript.ignoreBuildErrors` через env `SKIP_TYPECHECK=1`), бо CI вже gate'ить `tsc`; або звузити `tsconfig.include`.
3. Виправити `.dockerignore`; прибрати `npx prisma generate` ×2 у workflow і ×1 у Dockerfile; прибрати другий `docker compose up --build`.
4. Злити `verify-db` у `ci` (один `npm ci`), inline-скрипт → vitest-тест за `DATABASE_URL`, `migrate diff --exit-code`.
5. Тонкий `tools`-target (deps + prisma CLI + `prisma/`), без `.next`; run-образ без `seed-data`; `USER node`, `HEALTHCHECK`; `ARG` замість `ENV` для placeholder-секретів.
6. `shadcn` → devDependencies; `dotenv` → явна залежність.

### Tier 1 — quick wins у коді

7. `recalcDocument`/`recalcAndEnforce` → `lib/documents/recalc.ts` (не `"use server"`); усі читання через `tx`; recalc всередині tx у `finalize`; `updateMany where status:"DRAFT"` у кожній мутації.

10. `actions/_shared.ts` (`ActionResult`, sentinels, `flattenZodError`); `lib/revalidate.ts` (`revalidateDocument(id)` тощо) замість 89 рядкових шляхів.
11. `buildEngineInput()` спільний для actions/queries; Decimal → string без float.
12. `next/dynamic({ ssr:false })` для `RichTextEditor`; розділити `ui-kit/index.ts` на server-safe і `client.ts`; `i18n-iso-countries` — з клієнта геть (статичний список / prop).

## 7. Що НЕ робити

- Не видаляти тести «щоб деплой став швидшим» — вони не в критичному шляху деплою і коштують ~1 с.
- Не колокейтити тести в `src/`.
- Не вводити моки Prisma — поточна ізоляція чистих модулів цінніша.
- Не міняти bigint-cents engine у `pricing.ts` — він коректний; чистити треба навколо нього.
